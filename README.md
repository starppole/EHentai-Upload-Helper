# 这是什么

一个ehentai自动上传整理分组助手，帮你简化枯燥的重复操作，附带简单的图片压缩功能（gif格式不支持）

## 为什么用这个

1.如果你使用原版上传功能，你将要（“一次上传的大小不应超过 500 MB”），但现在图片原档的大小越来越大，在一张图片的大小都可以达到20~30mb的情况下，总共几百张图片的画廊（gallery）里，一次上传10张照片并等待，重复几十次的行为就显得有点愚蠢。

2 如果你一次上传了100张图片，你等待上传进度条涨到了99%，但是最后一张图片的大小或者分辨率超过了官方限制（“图像：JPG 和 WebP < 20 MB, PNG < 50 MB, GIF < 10 MB；归档：ZIP。最大分辨率：20000 x 20000。”），bang！你这次的上传和等待的时间将全部作废。

## 它能做什么

1.一次性选择全部你要上传的图片/zip，脚本会帮你分析大小并且分组，自动连续不间断上传，无需任何后续手动操作

2.分析图片大小，大于官方限制的将自动压缩并回到队列

## 使用方法

下载Tampermonkey作为前置，新建用户脚本并复制代码，保存并刷新eh上传页面即可生效

## 5.细节

### 关于图片压缩：

1. 先读原图尺寸。
2. 如果宽高超过 20000 × 20000，先缩小到限制内。
3. 如果像素总量超过 `8000 万像素`，也会先缩小，防止 Canvas 爆内存。
4. 输出格式固定为：image/webp
5.每一轮先不缩尺寸，只降低质量：0.92，0.86，0.80，0.74，0.68，0.62，0.56，0.50，0.44，0.38
6.如果这一轮最低质量 0.38还是大于目标大小，就把宽高乘以 0.85，再重新从 0.92 质量开始试。
7.最多试 10 轮。
8.成功后文件名变成：原文件名_compressed.webp
9.10 轮后还压不到目标大小，就报：压缩后仍然超过限制

### 持久队列说明

持久队列用于解决上传完成后页面刷新的问题。

普通 `<input type="file">` 选择的 File 对象只存在于当前页面内存中。  
页面刷新后，浏览器会清空这些 File 对象，脚本无法继续访问之前选择的文件。

持久队列使用 File System Access API 保存文件句柄。  
刷新后，脚本通过文件句柄重新读取本地文件：

```js
const file = await handle.getFile();
```
这种方式不会复制文件本体到 IndexedDB，也不会额外存储几 GB 的图片或 ZIP。
